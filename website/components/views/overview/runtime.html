The real model, running in your browser

The Model Predictor page does not call a server and does not use a simplified copy. It runs the exact tuned LightGBM from models/lgbm_champion.txt in JavaScript.

861Trees exported
Notebook 07 writes every tree (split features, thresholds, categorical sets, leaf values) to js/generated/model_lgbm.js (2.9 MB). js/sandbox_engine.js walks each tree the same way LightGBM does, including its rules for missing values and categories, sums the leaves and applies the sigmoid.
16Inputs asked

The form asks for 16 of the 33 features: the ones a person can actually know about a subscriber, such as plan length, last payment, auto-renew, days to expiry, March listening and age. Asking for all of them would mean typing in a full payment history (number of payments, past cancellations, share of auto-renew payments, discounts, payment methods), which nobody has to hand.

The other 17 are handled like this: 3 presence flags are always 1; 6 are worked out from the inputs (for example, days since the last payment = plan length − days to expiry); about 8 history features are filled with the training median of subscribers with the same auto-renew and cancel status. Those 8 carry about 5% of the model's split gain, so the prediction is close to the real model's answer, but it illustrates the model rather than scoring a real subscriber. The page also shows how much each feature pushed the prediction up or down: along each tree's path, the change in node value at every split is credited to that split's feature, so the contributions plus a base value add up exactly to the log-odds (checked in website/tests/check_model_parity.mjs).
