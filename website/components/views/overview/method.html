Why one row per subscriber, and why a cutoff date

The business question is who to contact, so the unit is a subscriber, not a transaction or a day. Each table is aggregated up to 31 March 2017. Later data is not available when the business must decide, so using it would inflate the scores.

The cutoff alone is not enough here: plans expire during March, so some renewals are already in March billing. That is why notebook 08 repeats everything with a 1 March cutoff.

Why missing values are kept, not dropped

Missing data is not random in this dataset. A subscriber with no transactions churns at , against 9% overall (training split). Dropping them would remove the easiest and most important cases and bias every score.

So we keep everyone and add three flags (has_member, has_tx, has_logs). Logistic regression fills gaps with the training median; LightGBM learns which branch missing values should follow.

Why log-scaling only for logistic regression

Hours listened and amount paid are heavily right-skewed: a few subscribers have huge values. A linear model would let those dominate, so we apply log1p and standardise.

Trees only ask "is x above some split point?", and a log does not change the order of values, so trees get the raw values.

PR-AUCMain metric
Only 9% of subscribers churn, so models are ranked by PR-AUC. Its no-skill level is 0.09. We also report ROC-AUC, log loss and Brier. Precision, recall, F1 and accuracy are measured at the threshold. Accuracy has to beat 0.91, the score of always saying "renews".
τ = Threshold
A subscriber is flagged when the probability is at least τ. We pick the τ with the best F1 on validation and use it unchanged on test. F1 treats a missed churner and a false alarm as equally bad. If a miss costs more, a lower τ is better: see the cost explorer.
1 MarStrict check
March payments overlap the label window. So the same LightGBM is retrained with billing from before 1 March 2017 only and scored once on the same test subscribers. It keeps the 31 March settings, so if anything its score is slightly low. Results →
1 000Bootstrap resamples
Test scores get 95% intervals from 1,000 bootstrap resamples. A difference between two models uses a paired bootstrap: both are scored on the same resample (1,000 resamples; 500 for the ablation and the strict check). The intervals cover test sampling only. They do not cover training with another seed, a later month, or why people churn.
1 splitReused validation
One validation split chooses the number of trees, the 30 Optuna trials, the model and the threshold. Picking the best of many tries makes validation slightly optimistic, which is why test scores are a little lower (Does it hold up?). Quote the test score.

How to read the intervals

0.9644 [0.9624, 0.9664] is a 95% interval: another test set of this size would land in this range about 95% of the time. For a difference such as +0.0083 [0.0073, 0.0093], an interval fully above zero means the second model is reliably better. One that crosses zero means a single test set cannot tell.

PR-AUC instead of accuracy

With 9% churners, predicting "nobody churns" is 91% accurate and completely useless. Accuracy rewards that.

PR-AUC looks only at how well the model ranks churners: at each cut-off, what share of flagged subscribers really churn (precision) and what share of churners are caught (recall). Its no-skill level equals the churn rate, 0.09, so the scale is honest for imbalanced data (Saito and Rehmsmeier, 2015).

Bootstrap and paired bootstrap

Bootstrap: draw 189,338 test subscribers with replacement from the test set, recompute the score, repeat 1,000 times, and take the 2.5th and 97.5th percentiles.

Paired: to compare two models, both are scored on the same resample and we keep the difference. Subscribers that are hard for one model are usually hard for the other, so pairing removes that shared noise. The interval for the difference is much tighter.

Choosing the threshold on validation

The model gives probabilities; contacting someone needs a yes or no. We tried thresholds from 0.01 to 0.97 on the validation split and kept the one with the highest F1 (0.45).

Picking it on test would make the test F1 optimistic, because the threshold would be fitted to those exact subscribers.

Test split used once

Every decision (features, models, settings, threshold, feature sets) was made on training and validation data. The test split was scored once, at the end. So its numbers estimate how the model does on new subscribers, not how well we tuned.

05Baseline and methods/ 16

From a constant guess to tuned boosting

Every model outputs a churn probability. The learned ones are trained on the training split, and every setting is chosen on validation. The test split plays no part.

Why these three model families

After the two baselines, each model tests one idea. Logistic regression asks if a straight-line boundary is enough. Random forest asks if thresholds and interactions matter, such as auto-renew off and a plan about to expire. LightGBM asks if trees that correct each other do better still. These are the three main families for tabular data, and the gains level off (tuning adds only +0.0025 PR-AUC), so another family is unlikely to change the answer.

Why baselines first

A score like PR-AUC 0.96 means nothing on its own. The majority baseline shows the no-skill level (0.0899, the churn rate). The auto-renew rule shows what a business gets from one flag and no model (0.3164).

Every model in the ladder has to beat the one below it. If a complex model lost to the rule, that would point to a bug, not a finding.

Gradient-boosted trees (LightGBM)

Boosting builds trees one after another. Each new tree learns the errors left by the trees before it. Its output is added with a small weight, the learning rate.

  • num_leaves = 50: how complex each tree can be.
  • learning rate 0.067, 861 trees: small steps, many trees.
  • row and column sampling, L2 penalty: stop the trees from memorising the training set.

It suits churn because the signal sits in thresholds, such as days until expiry, and in combinations, such as auto-renew off and a plan about to expire.

Optuna hyperparameter search

Optuna's TPE sampler looks at the trials so far and tries new settings near the ones that did well. We ran 30 seeded trials, each scored by validation log loss, and kept the best: trial 14, log loss 0.0423.

The test split was never used.

Why models are chosen by log loss, not PR-AUC

We report PR-AUC but select by validation log loss. Log loss is lowest only when the probabilities are honest, and a business needs honest probabilities to set a threshold. It is also smooth, which suits tuning.

Here the two agree: the best model by log loss also has the best validation PR-AUC (0.9686).

Considered, but not used
  • Survival models: they need a time axis. Here the outcome is one fixed 30-day window.
  • Feature selection: skipped, so no choice depends on held-out data. Trees ignore weak features anyway.
Why we did not reweight the classes

Only 9% of subscribers churn. Reweighting churners would raise recall, but a predicted 30% would no longer mean 30% churn.

We keep honest probabilities and handle the imbalance in the metric (PR-AUC) and the threshold instead.
